# opencode-telegram-slow-llm

**Telegram-мост для [opencode](https://opencode.ai), сделанный для медленного локального инференса.**

[🇬🇧 English](README.md) · 🇷🇺 Русский

На локальной модели в 5–15 токенов в секунду обычная задача агента — это несколько минут размышлений, вызовов инструментов и подтверждений. Мосты, написанные под быстрые облачные модели, на этом ломаются: обрывают задачу по тайм-ауту, показывают застывшее «печатает…», перестают читать чат, пока модель работает, а кнопки подтверждений истекают раньше, чем их кто-то увидит. Этот мост сделан именно для медленного случая. Собран и проверен на Qwen3.8-Flash-Next (MoE на 125B) на одной ноутбучной видеокарте 16 ГБ через [qwfnfer](https://github.com/cakescats/QwFNfer-Secure-RU), это примерно 10–12 токенов в секунду.

Бот общается с пользователями по-русски.

## Что он делает для медленного инференса

- **Всегда слушает чат.** Опрос Telegram не зависит от идущей задачи: `/stop`, кнопки подтверждений, пароль нового пользователя и другие чаты обрабатываются, пока модель ещё работает. Сообщение, отправленное во время задачи, встаёт в очередь, и бот об этом говорит.
- **Одно «живое» сообщение с размышлениями, правится каждые 3 секунды:** сколько идёт задача, текущий шаг, последний промежуточный итог агента и абзац размышлений, который модель пишет прямо сейчас (он сменяется, а не дописывается, так что сообщение остаётся коротким). Никаких новых сообщений на каждое обновление.
- **Ответ приходит отдельным сообщением** после размышлений, а сообщение размышлений превращается в «💭 Размышления · 1:12».
- **Терпеливые тайм-ауты.** Задача прерывается только после 20 минут без единого события и никогда — пока ждёт вашей кнопки. Подтверждение ждёт 10 минут, с обратным отсчётом в сообщении. Оба срока настраиваются.
- **Подтверждения оставляют историю, а не мусор.** Запрос приходит сообщением с кнопками и обратным отсчётом («через 0:20 само: ⛔ отклонить»). Когда на него ответили — вы, срок или другое окно, — это сообщение удаляется, а в сообщение размышлений записывается строка: «✅ bash: ls -la · разрешено один раз · ждал 0:12». Сообщение размышлений остаётся последним в чате и хранит все решения по задаче.
- **Настройки для каждого чата, из меню** (⚙️ Настройки, правится на месте, хранится на диске): спрашивать всё · правки сами, команды спрашивать · **разрешено всё без запросов** · только чтение; что делать с запросом без ответа (отклонить или разрешить один раз) и через сколько (от 30 с до 10 мин); быстрый режим.
- **`/fast`** — ответы без размышлений (добавляет `/no_think`, его понимают qwfnfer и другие серверы Qwen), на простых вопросах в разы быстрее.
- **Переживает перезапуски.** Связка «чат ↔ сессия» хранится на диске; запросы разрешений, которые поток событий пропустил, бот сам забирает у opencode раз в 30 секунд и присылает кнопками. Понимает и старый (`permission.updated`), и нынешний (`permission.asked`) формат событий opencode.
- **Один бот на токен.** Мост запускается только в процессе службы (`OPENCODE_TELEGRAM_BRIDGE=1`), поэтому opencode Desktop, загружая тот же плагин, не запускает второй опрос и не устраивает конфликт `getUpdates`.
- **Ненадёжная сеть:** запросы к Telegram идут по свежему соединению с коротким тайм-аутом и повторяются; следующая правка никогда не ждёт предыдущую.
- **Без вывода команд в размышлениях:** вывод инструментов и код идут отдельными частями и в сообщение размышлений не попадают; показан только абзац, который модель пишет прямо сейчас.

Плюс базовое: вход по паролю (кто прислал пароль — авторизован навсегда; 5 неверных попыток блокируют чат на 10 минут), клавиатура команд под полем ввода и меню команд Telegram, своя модель и режим разрешений для каждого чата.

## Что нужно

- opencode 1.18 или новее (проверено на 1.18.32).
- Linux со службами systemd пользователя (подойдёт всё, что умеет держать `opencode serve` в фоне; скрипт рассчитан на systemd).
- Токен бота от [@BotFather](https://t.me/BotFather).

## Установка

```bash
git clone https://github.com/cakescats/opencode-telegram-slow-llm.git && cd opencode-telegram-slow-llm
```

```bash
scripts/install.sh --project ~/путь/к/проекту
```

Скрипт копирует `plugin/telegram.ts` и `agent/telegram.md` в `~/.config/opencode` (старые версии — в `~/.config/opencode/backup/`), создаёт `~/.config/opencode/telegram.env` из примера, если его нет, пишет `~/.config/systemd/user/opencode-telegram.service` с путём к проекту и случайным паролем сервера (существующий сохраняет), включает и запускает службу.

Затем впишите токен бота и пароль в `~/.config/opencode/telegram.env` и перезапустите:

```bash
systemctl --user restart opencode-telegram
```

Откройте бота в Telegram и отправьте ему пароль.

## Управление

| | |
|---|---|
| Перезапуск (после правки `telegram.env` или обновления) | `systemctl --user restart opencode-telegram` |
| Остановить / запустить | `systemctl --user stop opencode-telegram` · `systemctl --user start opencode-telegram` |
| Работает ли | `systemctl --user status opencode-telegram` |
| Журнал службы | `journalctl --user -u opencode-telegram -f` |
| Журнал моста (в логе opencode) | `grep -aE 'telegram bridge\|poll\|permission\|stuck' ~/.local/share/opencode/log/opencode.log \| tail` |
| Обновить | `git pull && scripts/install.sh --project ~/путь/к/проекту` |
| Запуск при загрузке без входа в систему | `loginctl enable-linger $USER` |

Нормальный старт пишет в журнал `telegram bridge ready as @ваш_бот … stuck=20m permission=10m`.

Перезапуск службы обрывает идущую задачу и теряет сообщения в очереди — после него отправьте их ещё раз.

## Настройки (`~/.config/opencode/telegram.env`)

| Переменная | По умолчанию | |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | — | обязательно |
| `TELEGRAM_PASSWORD` | — | пароль для новых пользователей; меняется и из чата: `/password <новый>` |
| `TELEGRAM_ALLOWED` | — | постоянный список разрешённых id чатов и пользователей |
| `TELEGRAM_AGENT` | `build` | агент opencode; `telegram` — тот, что в `agent/telegram.md` |
| `TELEGRAM_MODEL` | по умолчанию opencode | `provider/model` |
| `TELEGRAM_PERMISSIONS` | `ask` | режим по умолчанию для чатов, где его не выбрали: `ask` · `edits` (правки сами, команды спрашивать) · `allow` (без запросов) · `deny` (только чтение) |
| `TELEGRAM_STUCK_MIN` | `20` | минут без событий до прерывания задачи |
| `TELEGRAM_PERMISSION_MIN` | `10` | сколько ждёт подтверждение в чатах, где срок не выбран (⚙️ Настройки) |
| `TELEGRAM_DEBUG` | `0` | `1` — писать в журнал каждый тип события |

Рядом лежат файлы состояния: `telegram-users.json` (авторизованные id), `telegram-settings.json` (настройки каждого чата) и `telegram-sessions.json` (чат ↔ сессия). Удалите второй, чтобы все чаты начали с новой сессии.

## Команды

Кнопки под полем ввода: ⏹ Стоп · 🆕 Новая · ⚡ Быстро · 📊 Статус · 📂 Сессии · ⚙️ Настройки.

`/new` новая сессия · `/stop` прервать · `/fast` ответы без размышлений (вкл/выкл) · `/status` · `/sessions` · `/use <id>` подключиться к сессии · `/model [provider/model]` · `/settings` · `/permissions ask|edits|allow|deny` · `/password <новый>` · `/who` · `/revoke` выйти из бота · `/menu` показать кнопки · `/help`

## Если что-то не так

- **Бот совсем не отвечает.** Проверьте `systemctl --user status opencode-telegram`, затем что `TELEGRAM_BOT_TOKEN` задан, а в журнале есть `telegram bridge ready`. Если в журнале `Conflict` — тот же токен опрашивает другой процесс: `OPENCODE_TELEGRAM_BRIDGE=1` должна быть только у службы.
- **Сообщения копятся, модель простаивает.** Скорее всего, агент ждёт подтверждения. В сообщении размышлений будет «🔐 ждёт вашего решения»; кнопки приходят отдельным сообщением, а если потерялись — бот пришлёт их заново в течение 30 секунд.
- **В ответе `Cannot connect to API`.** Сервер модели выключен или перезапускается; отправьте сообщение ещё раз, когда он поднимется.
- **Сервер модели отвечает 401.** Он требует ключ: пропишите `options.apiKey` у провайдера в `opencode.json`.

## Безопасность

- `telegram.env`, список пользователей и файл службы создаются с правами 0600 — так и оставьте.
- **Не давайте агенту делать `curl` к Telegram API с токеном.** opencode записывает в журнал каждую выполненную команду, и токен окажется в `~/.local/share/opencode/log/opencode.log`. Если это случилось — перевыпустите токен у @BotFather (`/revoke`) и впишите новый в `telegram.env`.
- Спрашивать по умолчанию — не случайно: любой, кто знает пароль, может заставить агента выполнять команды в вашем проекте. «Разрешено всё» включается для отдельного чата в ⚙️ Настройки, с предупреждением.
- Сервер opencode слушает только 127.0.0.1 и защищён `OPENCODE_SERVER_PASSWORD`.
